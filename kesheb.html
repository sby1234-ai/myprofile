PRINCIPLES상태를 부풀리지 않는 세 가지 원칙

확인 불가 ≠ 정상

값을 읽지 못한 항목은 정상으로 보이지 않게 "확인 불가"로 따로 표시하고, 다음에 할 일을 함께 적습니다.

접수 ≠ 성공

조치 요청이 접수됐다는 응답만으로 성공이라 하지 않습니다. 서버가 실제 효과가 적용됐다고 알려 줄 때만 성공으로 표시합니다.

조회 실패 ≠ 취약점 없음

취약점 정보를 조회하지 못했거나 아직 조회하지 않았다면 "알려진 항목 없음"으로 표시하지 않습니다.

TROUBLESHOOTING막혔던 곳과 해결

17단계 · AI 연결

계정 연결 실패를 "내 코드 문제가 아님"으로 분리해 보고

상황
AI 게이트에 계정을 연결하는 단계에서, 다시 로그인하고 다른 브라우저로 바꿔도 연결이 계속 막혔습니다.
확인
앱 화면에 나온 상태 코드와 브라우저 네트워크 요청을 확인했더니, AI 게이트 서버가 401(인증 실패)로 응답하고 있었습니다. 제가 고칠 수 있는 학생 코드가 아니라 운영 측 서버 인증 단계에서 막힌 것이었습니다.
행동
추측으로 코드를 바꾸지 않고, 상태 코드와 401 응답을 근거로 붙여 담당 강사에게 서버 쪽 문제로 보고했습니다.
결과
17단계 통과. 같은 코드인데 판정 항목 하나가 통과와 확인 불가 사이를 오간 것도 관찰해, 판정이 매번 같지는 않다는 점을 기록했습니다.
22단계 · 재현 가능한 인수인계

문서와 저장소가 어긋난 세 곳을 찾아 맞춤

상황
첫 제출에서 세 항목이 미충족이었습니다. 모두 "문서에 적은 것과 저장소에 실제로 올라간 것이 다르다"는 문제였습니다.
원인·해결
① 버전 불일치: 문서 버전을 PC 작업본 기준으로 적어, 커밋된 설정 파일과 달랐습니다 → 커밋 기준으로 정정.
② 백업 계획 없음: 백업 명령에 대상 목록이 빠져 있었습니다 → 백업 문서에 전체 경로와 사전 확인 절차 추가.
③ 파일 지문 불일치: Windows 작업본(CRLF 줄바꿈) 기준으로 해시를 적어 저장소(LF)와 달랐습니다 → Git 지문과 LF 기준 해시를 함께 기록.
결과
새 빈 폴더에 저장소를 받아 실행 → 종료 → 재실행이 되는 것을 로그로 남기고 통과했습니다. 21단계도 문서의 지원 버전 표(Node 24 미만 미지원)가 실제 실행 도구(22~24 허용)와 달라 한 번 막혔고, 도구 기준으로 고쳐 통과했습니다.

SCOPE어디까지 만들었나

완성된 보안 제품이 아니라, 관제 화면과 판정 표시를 단계별로 구현한 과제입니다.

만든 것

  • 저장된 경보와 접속 기록을 내 권한 범위에서 보여 주는 화면
  • 업무 앱 접근 판정과 그 이유 표시
  • 근거가 연결된 AI 사건 설명, 사람이 확인하는 조치 제안과 서버 처리 결과
  • 라이브러리 취약점 대조, 내 PC 상태 대시보드
  • 실행 안내·학생 설명서·재현 기록·백업 계획 문서

만들지 않은 것

  • 실시간 탐지 엔진, 실제 차단·조치를 실행하는 장치
  • 회사 서버와의 실제 연결 — 접근 제어 서버·연결 어댑터·개인 인증서가 필요하며 과정에서 발급하지 않음
  • 설치 프로그램 포장(이번 과정에서 하지 않음)
