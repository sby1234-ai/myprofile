## AI와 나의 판단 (과제 8 — 패스키 로그인)

- **AI에게 맡긴 일**: Supabase Edge Function 코드 작성(등록·로그인·로그아웃·비공개 자료·패스키 관리), WebAuthn 데이터 변환 로직, DB 테이블 구조 설계
- **내가 판단한 일**: 실제 사이트에서 등록과 로그인을 직접 반복하며 요청·응답 로그를 확인하고, 로그를 근거로 무엇이 잘못됐는지 짚어 수정하게 했습니다. 패스키는 USB 보안 키가 아니라 Google 비밀번호 관리자에 저장하는 방식으로 정했습니다.
- **AI 말을 안 들은 일**: AI가 만든 코드를 그대로 믿지 않고, 실제 동작 로그로 확인된 것만 반영했습니다. 그 과정에서 AI가 만든 설정끼리 충돌한 문제 4가지를 찾아 고쳤습니다.

### 테스트 중 찾아서 고친 문제

| 문제 | 원인 | 수정 |
| --- | --- | --- |
| 등록 시 Windows "USB 보안 키" 창만 뜸 | 등록 옵션이 외부 보안 키만 허용(`cross-platform`)하고 저장형 패스키를 원하지 않음(`residentKey: discouraged`) | 제한을 지우고 저장형 패스키(`residentKey: required`)로 요청 → Google 비밀번호 관리자에 저장됨 |
| 등록·로그인 서명 검증 실패 | 브라우저는 본인 확인(PIN)을 생략하도록 요청했는데, 서버는 본인 확인을 필수로 검사 | 등록·로그인 모두 본인 확인을 `required`로 요청 |
| 로그인 후 세션 교환 실패 | 1회용 토큰 해시를 6자리 OTP 자리에 넣어 전달 | `token_hash`로 전달하도록 수정 |
| 재배포 후 서명 검증 오류 | 배포된 함수에서 사이트 주소(RP_ID) 값이 비어 있음 | 값이 비어 있으면 실제 사이트 주소를 쓰도록 수정 |
