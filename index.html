직접 구축한 실습

교육 과정에서 방화벽부터 IDS/IPS, 모니터링까지 직접 구축한 실습입니다. 화면은 실습용 사설망 주소만 보이며, 계정·비밀번호는 넣지 않았습니다.

네트워크·방화벽·VPN

GNS3 · Cisco ASAv · pfSense

방화벽 규칙 5개 · 차단 확인OpenVPN 접속 확인OSPF 이웃 유지

GNS3에서 라우터·방화벽·VLAN을 구성하고 pfSense OpenVPN까지 연결했습니다.

자세히 보기

구성라우터 4대와 방화벽을 OSPF로 묶고, 외부망을 VLAN 3개(네트워크·시스템·침투 테스트)로 나눴습니다. 방화벽 규칙 5개와 pfSense OpenVPN을 구성했습니다.

확인규칙을 적용하기 전에 통신이 되는 것을 기준으로 남기고, 적용한 뒤 ACL 히트 카운트로 차단이 실제로 동작하는지 확인했습니다. 규칙마다 OSPF 허용을 맨 위에 넣어 이웃이 유지되는 것도 확인했습니다. OpenVPN은 윈도우 PC로 접속해 터널 주소 할당과 AES-256-GCM 암호화까지 확인했습니다.

막힌 곳pfSense에서 WAN에 잘못 넣은 고정 IP의 게이트웨이가 남아 기본 경로가 깨졌고, 패키지 저장소에 접속할 수 없었습니다. 원인을 찾아 VM을 다시 설치하고 WAN은 DHCP로 두는 것으로 해결했습니다.

IDS/IPS

Snort3 · Suricata · Kali

경계 ACL + 센서 Suricata 2계층ICMP·SSH·HTTP 3종 탐지 확인

Snort3와 Suricata를 직접 구축하고 공격 트래픽으로 시험했습니다.

자세히 보기

구성Snort3를 소스부터 빌드해 ICMP 탐지 룰로 IDS를 만들고, Rocky 서버에 Suricata를 올려 직접 쓴 룰과 공개 룰셋(ET Open)을 적용했습니다.

확인Kali에서 hping3로 ICMP 플러딩을 보내고, Snort의 알림과 Suricata의 알림 로그(fast.log)로 탐지되는 것을 확인했습니다. 라우터 ACL에는 log를 붙인 탐지 룰 3개(ICMP·SSH·HTTP)를 작성해, 탐지 로그에 ICMP 5건·SSH 2건·HTTP 2건이 일치하는 것도 확인했습니다.

모니터링·SIEM·로그

Zabbix · OSSEC · Wazuh · PMM · LogAnalyzer

Zabbix↔OSSEC 상호 감시 확인Wazuh 에이전트 ActivePMM 등록 확인LogAnalyzer 로그 조회

Zabbix·OSSEC·Wazuh·PMM·LogAnalyzer를 각각 구축했습니다.

자세히 보기

구성Zabbix 서버, OSSEC 서버와 에이전트, Wazuh 서버와 대시보드, Docker 기반 PMM(DB 모니터링), rsyslog와 MariaDB 기반 LogAnalyzer를 각각 구축했습니다. Zabbix와 OSSEC은 서로를 감시하도록 연결했습니다.

확인OSSEC에서 Zabbix가 Active로 올라오고, Zabbix 화면에서 OSSEC 호스트가 정상으로 보이는 것을 양쪽에서 확인했습니다. Wazuh 대시보드에서는 웹·DB 서버의 에이전트가 Active인 것을 확인했습니다.

막힌 곳LogAnalyzer가 DB 로그를 읽지 못했습니다. 설정 파일에 걸린 SELinux 읽기 전용 권한, 웹 서버의 DB 연결 허용, 설치 마법사에 잘못 넣은 DB 이름을 하나씩 찾아 고쳤습니다.

리눅스 서버 구축

Rocky Linux · VM 4대

VM 4대 구축요구사항 동작 확인

VM 4대로 DNS·웹·DB·NFS·FTP 서버를 나눠 구축했습니다.

자세히 보기

구성DNS(BIND), 웹(Apache HTTPS)·DB(MariaDB)·Samba·로그 서버, NFS, FTP를 VM 4대로 나눠 구축하고 도메인으로 접속되게 했습니다.

확인서버 간 통신, 도메인 접속, 공유 디렉토리와 FTP 접속, 로그 확인이 요구사항대로 동작하는 것을 확인했습니다. DB는 기본 입출력, 계정과 권한 관리, 백업, Master-Slave 복제까지 실습했습니다.

보안 점검 스크립트

Shell · KISA 2026 가이드 · 팀 프로젝트

KISA 20개 항목 · 상 15 · 중 3 · 하 2점검 + 조치 스크립트 완성

팀 프로젝트에서 파일·디렉토리 관리 파트를 맡았습니다.

자세히 보기

구성Unix 서버 보안 취약점 점검 스크립트를 팀원끼리 파트를 나눠 만들었고, 저는 '파일 및 디렉토리 관리' 파트(가이드 20개 항목)를 맡았습니다. 대상은 Rocky·RHEL 계열입니다.

확인항목마다 점검 내용, 현재 설정(증거), 판정(양호·취약·수동확인·해당 없음), 취약한 부분을 화면에 출력하는 점검 스크립트와, 취약 항목을 고치는 조치 스크립트를 완성했습니다.

점검 범위KISA 가이드의 '파일 및 디렉토리 관리' 20개 항목입니다(중요도 상 15·중 3·하 2). 시스템 주요 파일(passwd·shadow·hosts·services 등)의 소유자·권한, SUID·world writable·숨김 파일 같은 위험 파일, UMASK·홈 디렉터리·접속 제한 설정을 점검합니다.

공격 관점 CTF

VulnHub 부트투루트 · Kali · 자작 머신

박스 8개 완료자작 CTF 머신 “VaultCorp” 제작 완료

VulnHub 박스로 침투·권한 상승을 익힌 뒤, 직접 다단계 CTF 머신을 설계·제작하고 공격 체인 전체를 검증했습니다.

자세히 보기

구성VulnHub 박스 8개를 완료했습니다(EvilBoxOne, Momentum, Momentum2, FALL, CHRONOS, Earth, doubletrouble, corrosion). 파일 읽기 취약점, 명령어 인젝션, 업로드 필터 우회, sudo·SUID 권한 상승을 반복해 익혔습니다.

자작자작 CTF 머신 “VaultCorp”(난이도 medium, 목표 약 2.5시간)를 직접 설계·제작했습니다. “해고된 전임 관리자가 남긴 흔적” 스토리라인으로 정찰 → 초기 침투 → 내부 이동 → 권한 상승을 다단계로 구성했습니다.

공격 체인숨겨진 개발 서브도메인 정찰 → 노출된 .git 소스 복원 → 업로드 필터(확장자 화이트리스트·이미지 형식 검증) 우회로 웹쉘 획득 → 서버 설정 파일에서 DB 자격증명 탈취 → 비밀번호 해시·암호 압축 파일 크랙으로 내부 계정 확보 → SUID 바이너리의 PATH 하이재킹으로 root 권한 상승.

검증·문서화공격자(Kali) 입장에서 처음부터 끝까지 직접 풀어 각 단계가 의도대로 통과하는지 검증하고, 명령별 의도와 출력 해석·방어 관점까지 담은 풀이 문서(워크스루)를 작성했습니다.
